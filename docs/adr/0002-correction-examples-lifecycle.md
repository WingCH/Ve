# 修正例子獨立保留，並只供同一 App 的後續判斷參考

人工修正例子獨立於通知紀錄保留。刪除通知或因筆數上限淘汰通知後，仍保留修正例子，並提供「清除修正例子」操作。這以持續保留使用者的修正為優先，同時需要明確的清除入口。使用者於 2026-10-03 在設計訪談 Q5–Q6 確認此取捨。

每次判斷帶同一 App 最近 10 條修正例子。例子包含通知內容、人工指定的「應轉發／不應轉發」與可選原因。這限制跨 App 的相互影響，並避免每次累積送出所有例子。修正只影響後續判斷；當次通知需要補發時，由使用者另外操作「補發到 Bark」。使用者在 Q5、Q7 確認這些行為。它們是設計決定，實際改善判斷的效果仍待模型驗證。

原有通知紀錄受筆數上限影響，原文：「while ([logs count] > [self logLimit])」及「[logs removeLastObject];」— [LogManager.m:128](../../Manager/LogManager.m#L128)，核對版本 `f1ce706ccd15411319fb63f3acb9f07fc8b5b710`。依據關係：程式碼直接顯示舊通知會被移除；因此只把修正保存在通知內無法滿足獨立保留需求。
